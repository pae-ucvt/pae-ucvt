## 1. Зачем нужны субагенты

Представь, что ты работаешь один. Если задача простая — открыть файл, что-то поправить — ты справляешься сам. Но если задача большая (написать статью, сделать сайт, проверить код), удобно позвать помощников.

Субагенты — это те самые помощники. Главный агент (Build) — как руководитель проекта. Он раздаёт задачи, а субагенты делают свою часть и возвращают результат.

Когда стоит задуматься о субагентах:
- Задача большая и состоит из разных этапов
- Ты делаешь одно и то же регулярно
- Нужны разные навыки (поиск информации, написание текста, проверка)

Если Build справляется за один-два запроса — субагенты не нужны. Усложнять без причины не стоит.

---

## 2. Что есть в Open Code

В Open Code два вида агентов.

**Главные агенты (primary)** — те, с кем ты общаешься напрямую. Переключаются через список внизу экрана.

| Имя | Режим | Что делает |
|-----|-------|------------|
| Build | главный | Может всё: читать, писать, запускать команды. Работает по умолчанию |
| Plan | главный | Только думает. Не может менять файлы и запускать команды без спроса |

**Субагенты** — помощники, которых Build зовёт для конкретных задач. Ты тоже можешь позвать их сам, написав `@имя` в сообщении.

В Open Code уже есть три готовых субагента:

| Имя | Что делает |
|-----|------------|
| `@general` | Универсальный помощник. Может читать, писать, запускать команды |
| `@explore` | Только читает. Быстро ищет по файлам, отвечает на вопросы |
| `@scout` | Только читает. Изучает внешние библиотеки и документацию |

Есть ещё скрытые системные помощники (их не видно, они работают сами):
- **compaction** — сжимает длинный разговор, когда тот становится слишком большим
- **title** — придумывает названия беседам
- **summary** — делает краткое содержание разговора

## 3. Как устроен субагент внутри

Субагент — это просто текстовый файл с настройками. У каждой строчки в этом файле своё назначение:

- **имя** — как ты будешь его звать (`@имя`)
- **описание** — для чего он нужен, чтобы Build понимал, когда его вызывать
- **инструкция** — что именно ему делать
- **модель** — какой мозг у него будет (можно выбрать подешевле)
- **разрешения** — какие кнопки ему нажимать можно, а какие нельзя

Где лежат эти файлы:
- В папке проекта: `.opencode/agents/имя.md`
- У всех проектов на компьютере: `~/.config/opencode/agents/имя.md`
- Или прямо в настройках: `opencode.json`

## 4. Три способа работать с помощниками

### Способ 1 — цепочкой (последовательно)

Один помощник делает дело, потом передаёт результат следующему.

```
Вы просите написать статью
  → Исследователь собирает факты
  → Редактор превращает факты в текст
  → Проверяющий ищет ошибки
  → Вы получаете готовую статью
```

### Способ 2 — одновременно (параллельно)

Несколько помощников работают каждый над своей частью. Быстро, но нужен чёткий формат, чтобы они не запутались.

```
Вы просите информацию о нейросетях
  ├─ Помощник A: ищет официальное определение
  ├─ Помощник B: ищет примеры из жизни
  └─ Помощник C: ищет риски и ограничения
          ↓
  Сборщик соединяет всё вместе
          ↓
  Вы получаете полный ответ
```

### Способ 3 — по ролям

У каждого помощника своя профессия, записанная заранее.

```
Build (руководитель)
  ├─ Исследователь: ищет факты
  ├─ Аналитик: делает выводы
  ├─ Писатель: пишет понятный текст
  └─ Ревьюер: проверяет ошибки
```

Можно смешивать все три способа — это нормально.

## 5. Первый запуск — попробуй прямо сейчас

Ничего настраивать не надо. Просто отправь Build такое сообщение:

```
@explore опиши, какие файлы есть в этом проекте
```

### Что ты увидишь

После отправки:

1. **Кнопка слева начнёт мигать** — цветом того агента, которого ты позвал. У `@explore` цвет оранжевый, у `@general` — голубой. У каждого агента свой цвет.
2. **Под строкой ввода появится имя агента** — цветным шрифтом и с описанием задачи.
3. **В правом нижнем углу появится стрелка** — нажми на неё, чтобы открыть вкладку с ответом.
4. **Откроется дочерняя вкладка** — там будет результат работы субагента.

Когда субагент закончит, ты можешь вернуться к основному разговору.

### Можно запустить несколько сразу

```
Запусти отдельного @general на задачу: придумай 3 идеи для постов в соцсети про этот проект, и второго @general на задачу: напиши 5 вариантов заголовка для лендинга
```

Build сам запустит обоих, подождёт результаты и вернёт тебе общий ответ.

Быстрый запуск без ролей удобен, но для серьёзной работы лучше создавать субагентов с чёткими инструкциями.

## 6. Как создать своего субагента

В Open Code нет кнопки «Создать агента» — всё делается через файлы. Не пугайся, это просто.

### Способ 1 — создать файл

Создай папку `.opencode/agents/` в корне проекта (если её нет). Внутри создай файл `reviewer.md` и напиши в нём:

```
---
description: Проверяет код на ошибки и качество
mode: subagent
permission:
  edit: deny
  bash: deny
---

Ты — ревьюер. Проверяй код на ошибки, безопасность и качество.
Не вноси изменения — только давай советы.
```

Теперь в любом сообщении можно написать `@reviewer` — и он будет работать.

### Способ 2 — добавить в настройки проекта

Можно прописать субагента прямо в файле `opencode.json` (он лежит в корне проекта):

```json
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "code-reviewer": {
      "description": "Проверяет код на ошибки",
      "mode": "subagent",
      "permission": {
        "edit": "deny"
      },
      "prompt": "Ты — ревьюер. Проверяй код на ошибки и качество."
    }
  }
}
```

### Что писать в настройках

- **description** (обязательно) — описание, чтобы Build понимал, когда звать этого помощника
- **mode** — всегда `subagent` для субагента
- **model** — какая модель будет работать (если не указать — будет та же, что у Build)
- **prompt** — инструкция, что делать
- **permission** — что разрешено делать

## 7. Разрешения — что можно агенту, а что нельзя

В Open Code вместо «инструментов» используются разрешения (permissions). Смысл простой: каждому агенту дают ровно столько прав, сколько нужно для его работы. Не больше.

Основные разрешения:

| Ключ | Что даёт |
|------|----------|
| `read` | Читать файлы |
| `edit` | Менять файлы |
| `glob` | Искать файлы по имени |
| `grep` | Искать текст внутри файлов |
| `bash` | Запускать команды в терминале |
| `webfetch` | Загружать страницы из интернета |
| `websearch` | Искать в интернете |

Три варианта для каждого разрешения:
- `allow` — можно без спроса
- `ask` — спросить у тебя
- `deny` — нельзя

### Примеры

| Что разрешено | Что может делать агент |
|---------------|------------------------|
| только читать | Посмотреть код, но ничего не менять |
| читать + терминал | Посмотреть код и запустить проверки |
| читать + терминал + менять | Посмотреть, проверить и исправить |

## 8. Как вызывать субагентов и зачем это нужно

### Явный вызов

Просто напиши `@имя` в сообщении:

```
@explore найди в проекте все файлы с формами
```

Build увидит `@explore` и запустит его для этой задачи.

### Неявный вызов

Попроси Build самому решить, нужен ли помощник:

```
Сделай ревью кода. Если понадобится — используй субагента.
```

### Как это выглядит на экране

Когда Build запускает субагента:
- Кнопка слева начинает мигать цветом этого агента
- Под строкой ввода появляется его имя цветным шрифтом
- В правом нижнем углу появляется стрелка — нажать, чтобы открыть вкладку
- После завершения ответ виден в отдельной вкладке

### Зачем это нужно: экономия «головы»

У каждого агента есть **контекстное окно** — как кратковременная память. Когда оно заполняется, Open Code сжимает старые сообщения (это называется **auto-compaction**) и «забывает» детали.

Если дать сложную работу (например, прочитать 20 файлов) субагенту — он потратит свою память, а Build останется с чистой головой и будет думать быстрее.

Особенно полезно для:
- Поиска информации в интернете
- Чтения больших файлов
- Задач, которые можно делать одновременно

## 9. Какие настройки можно поменять

### Модель для субагента

По умолчанию субагент использует ту же модель, что и Build. Но можно поставить другую — например, подешевле для простых задач:

```json
{
  "agent": {
    "fast-researcher": {
      "description": "Быстрый поиск",
      "mode": "subagent",
      "model": "anthropic/claude-haiku-4-20250514",
      "permission": {
        "edit": "deny",
        "bash": "deny",
        "webfetch": "allow",
        "websearch": "allow"
      }
    }
  }
}
```

Экономия: дорогая модель для Build + дешёвая для субагента, который просто ищет информацию.

### Температура — насколько творческим будет ответ

- **0.0–0.2**: точный, сухой ответ (для анализа)
- **0.3–0.5**: средний (для обычной работы)
- **0.6–1.0**: творческий, разнообразный (для идей)

```json
{
  "agent": {
    "analyst": { "temperature": 0.1, "description": "Точный анализ" },
    "creative": { "temperature": 0.7, "description": "Генерация идей" }
  }
}
```

### Max steps — сколько шагов может сделать агент

Ограничение, чтобы агент не ушёл в бесконечные размышления:

```json
{
  "agent": {
    "quick-check": {
      "description": "Быстрая проверка",
      "steps": 3
    }
  }
}
```

### Color — цвет агента в интерфейсе

Каждому агенту можно задать свой цвет:

```json
{
  "agent": {
    "reviewer": { "description": "Ревью", "color": "#ff6b6b" }
  }
}
```

Можно hex-код (`#ff6b6b`) или имя: `primary`, `secondary`, `accent`, `success`, `warning`, `error`, `info`.

## 10. Task permissions — кто кого может вызывать

Можно запретить Build вызывать некоторых субагентов:

```json
{
  "agent": {
    "orchestrator": {
      "mode": "primary",
      "permission": {
        "task": {
          "*": "deny",
          "orchestrator-*": "allow",
          "code-reviewer": "ask"
        }
      }
    }
  }
}
```

Правила применяются по порядку: что написано позже — то и работает.

Ты всегда можешь вызвать любого субагента вручную через `@`, даже если в настройках написано «нельзя».

---

## 11. Скрытые субагенты (hidden)

Иногда удобно сделать субагента, которого не видно в списке подсказок `@`. Он будет вызываться только другими агентами, но не тобой:

```json
{
  "agent": {
    "internal-helper": {
      "mode": "subagent",
      "hidden": true
    }
  }
}
```

## 12. Пример: контент-завод на субагентах

Представь: Build получает ссылку на новость и превращает её в посты для соцсетей.

### Схема работы

```
Build (руководитель)
  ├── @content-writer:  превращает новость в посты для Telegram, Instagram, X и TikTok
  ├── @image-generator: создаёт картинку через нейросеть
  └── @video-agent:     делает короткое видео
          ↓
  Build собирает всё вместе
          ↓
  @publisher: публикует пост (может только читать и запускать команды — менять файлы нельзя)
```

### Как это работает

1. Ты кидаешь Build ссылку на новость
2. Build запускает трёх помощников параллельно — каждый мигает своим цветом
3. Помощники делают свою часть и возвращают результат
4. Build собирает всё вместе
5. Build передаёт результат `@publisher`, который публикует пост

### Важный урок

`@content-writer` может случайно сделать текст длиннее, чем позволяет соцсеть. API вернёт ошибку, но агент может сказать «всё хорошо». Поэтому важно прописывать чёткие правила: какой длины должен быть текст, какие бывают ошибки, как проверять результат.

В этом примере используются все три способа сразу:
- **Параллельно**: три агента работают одновременно
- **Последовательно**: результаты собираются → передаются Publisher
- **По ролям**: у каждого своя задача и свои разрешения

### Кому что разрешено

| Субагент | Что можно | Что нельзя |
|----------|-----------|------------|
| Писатель | читать, менять файлы | запускать команды |
| Художник | читать, запускать нейросеть | менять файлы |
| Видеоагент | читать, запускать генерацию видео | менять файлы |
| Публикатор | читать, запускать команды | менять файлы |

## 13. Когда субагенты нужны — а когда нет

**Нужны, если:**
- Задача состоит из нескольких этапов
- Этапы можно делать одновременно
- Ты делаешь это регулярно
- Хочешь, чтобы Build не забивал голову мелочами

**Не нужны, если:**
- Задача простая — на один-два запроса
- Build справляется сам
- Задача уникальная, нет смысла настраивать

### С чего начать

Начни с пары: **Build + один субагент** с конкретной ролью.

По шагам:
1. Сначала сделай задачу вручную — поймёшь, из каких шагов она состоит
2. Потом попроси Build делегировать часть работы субагенту
3. Постепенно улучшай: уточняй роли, форматы, правила проверки

## Словарь простыми словами

| Слово | Что значит |
|-------|------------|
| Build | Главный агент, с которым ты общаешься. Может всё |
| Plan | Главный агент, который только предлагает, но ничего не меняет |
| Субагент | Помощник, которого Build зовёт для конкретной задачи |
| Оркестрация | Build раздаёт задачи субагентам и собирает результаты |
| Permissions | Настройка «можно/нельзя» — что агенту разрешено делать |
| Явный вызов | Ты сам пишешь `@имя` в сообщении |
| Неявный вызов | Build сам решает, кого позвать |
| Последовательная работа | Один сделал → передал другому |
| Параллельная работа | Несколько делают одновременно каждый своё |
| Контекстное окно | Память агента — сколько информации он может помнить сразу |
| Auto-compaction | Сжатие старых сообщений, чтобы освободить память |
| Hidden | Спрятанный агент — не виден в подсказках, но работать может |
| Task permissions | Правила — кого Build имеет право запускать |

## Сравнение: Claude Code vs Open Code

| О чём речь | Claude Code | Open Code |
|------------|-------------|-----------|
| Как выглядят агенты | Файлы с настройками | Файлы с настройками |
| Где лежат в проекте | `.claude/agents/` | `.opencode/agents/` |
| Где лежат глобально | `~/.claude/agents/` | `~/.config/opencode/agents/` |
| Встроенные субагенты | нет | `@general`, `@explore`, `@scout` |
| Главные агенты | один | Build и Plan |
| Команда `/agents` | есть | нет |
| Создание агента | через `/agents` или файл | только через файл или настройки |
| Вызов | `@имя` или неявно | `@имя` или неявно |
| Спрятать агента | нельзя | можно через `hidden: true` |
| Кто кого может вызывать | без ограничений | можно настроить |
